# Installed game data and resource evidence

This report covers the installed **Sid Meier's Alpha Centauri** directory in the Steam CrossOver bottle. It records read-only static inspection of shipped resources and the first 12 bytes of three existing save files. It does not claim observed game execution. The parent investigation supplies the REA executable analysis.

Every `ASSET-*` reference below resolves to an exact source file, whole-file SHA-256, and line/byte span in [asset_evidence.json](asset_evidence.json). These are supplementary filesystem evidence identifiers, not REA Evidence IDs. Byte offsets are zero-based; excerpt end offsets are exclusive. Text line numbers are one-based and inclusive. The captured excerpt spans were checked against the original bytes.

| Finding | Evidence and assessment |
|---|---|
| Gameplay is extensively parameterized in text tables. | `alpha.txt:8–15` explicitly documents loading rules at startup and preferring scenario-local files (`ASSET-01`). `#RULES` at line 24 contains movement, food/mineral costs, combat multipliers, population caps, technology gates, and turn/year limits (`ASSET-02`). This establishes the shipped configuration contract; execution must be corroborated by the binary loader. |
| Terrain production and planet generation have separate parameter blocks. | `alpha.txt:132–196` documents nutrient/mineral/energy yields, then `#WORLDBUILDER` with land seeds, continents, rivers, latitude/temperature, rainfall, and fungus coefficients. `#WORLDSIZE` includes the numeric pair `40, 80` for Standard (`ASSET-04`). The exact map-cell algorithm and dimension interpretation are not established by these comments. |
| The technology model is a dependency graph with AI valuation inputs. | `alpha.txt:220–266` defines technology identifier, four AI weighting fields, two prerequisites, and effect flags (`ASSET-05`). For example, Nonlinear Mathematics at line 259 references `Physic` and `InfNet`. The weights are declared military/knowledge/infrastructure/colonization values. This does not recover how the AI combines them during play. |
| Unit templates combine reusable components. | Chassis, reactor, weapon/package, armor, and ability definitions appear in `alpha.txt:340–507` (`ASSET-06`–`ASSET-08`). `alphax.txt:559–614` documents templates referencing those lists, AI plan roles, automatically calculated cost/carry fields, and ability flags (`ASSET-09`). Its Formers row uses `Infantry`, the `Formers` package, `Scout` armor, plan 9, and the `Ecology` prerequisite. This is direct evidence of a composition-based unit data model. |
| Faction behavior and presentation share a declarative faction file. | `FACTION.TXT:9–107` documents aggression plus power/technology/wealth/growth preferences, starting technology, per-base modifiers, social modifiers, and political priorities (`ASSET-10`). `GAIANS.TXT:13–36` supplies concrete values: Ecology, −MORALE, −POLICE, ++EFFIC, +PLANET, and fungus nutrients (`ASSET-11`). Later sections provide separate land/sea base-name lists, lore, help text, and diplomacy templates (`ASSET-12`, `ASSET-13`). This establishes the parameters, not the underlying AI/diplomacy decision algorithm. |
| Dialogs use a documented text/template language. | `Script.txt:33–86` defines hash-prefixed control directives, bold/italic delimiters, explicit newline/centering markers, indexed string substitution, numeric/hex substitution, and grammatical gender/plurality forms (`ASSET-15`). It says the numeric ID controls ordinary substitutions: `$PLAYERNAME1` and `$NAME1` are equivalent. `menu.txt:5–50` stores menu labels/shortcut descriptions (`ASSET-16`). These files are UI text/control resources; arbitrary executable scripting was not established. |
| The expansion's resource tables extend a shared schema. | `alpha.txt` and `alphax.txt` both contain 89 technology rows, 9 chassis rows and 4 reactor rows. Their weapons/package rows differ 21→26, armor 10→14, abilities 24→29, and declared base-unit counts 14→23. `alphax.txt:1164–1196` explicitly names the seven original faction files plus seven `#NEWFACTIONS` and a custom-faction list (`ASSET-14`; complete table counts in the manifest). Technology rows include disabled entries; facilities include placeholders. These are data-record counts, not counts of runtime-accessible features. Executable selection of `alpha` versus `alphax` requires the parent's binary evidence. |
| The installed preferences request older rendering behavior with 3D audio enabled. | `Alpha Centauri.Ini:1–8` contains `ForceOldVoxelAlgorithm=1` under `[PREFERENCES]` and `ds3d=1`, `eax=1`, `DirectDraw=0` under `[Alpha Centauri]` (`ASSET-18`). `readme_ac.txt:227–237` documents DirectDraw disabling automatic resolution changes and the old-voxel option as a crash workaround; line 129 documents the DS3D/EAX options (`ASSET-19`, `ASSET-20`). The effective settings, driver path and rendered output were not observed. |

A concrete scenario override illustrates the relationship between the tables and gameplay. The normal `alpha.txt:610` Network Node row has cost **8**; the tutorial's `scenarios/Alpha Centauri Scenarios/2Build/alpha.txt:598` row has cost **2**. The adjacent schema explicitly says to multiply that field by the minerals multiplier, which is **10** in both rule files. Thus the declared unmodified costs are **80 minerals** and **20 minerals**, respectively, before any other in-game modifiers (`ASSET-02`, `ASSET-22`, `ASSET-25`, `ASSET-26`). The difference is directly observed in shipped files; confirmation that a particular run applied this override requires loader/runtime evidence.

The recursive directory inventory contains **1,683 files / 596,954,709 bytes**, including 760 `.pcx`, 140 `.cvr`, 354 `.wav`, 154 `.mp3`, 61 `.wve`, and 37 `.flc` filenames. Counts classify filenames only. Selected format checks provide firmer evidence:

- `palette.pcx`, `Gaians.pcx`, and `Cursor.pcx` each have PCX manufacturer `0x0A`, RLE encoding `1`, 8 bits per plane, one plane, 1024×768 bounds, and final 256-color palette marker `0x0C`. Exact header offsets are recorded in `ASSET-PCX-1` through `ASSET-PCX-3`. This supports indexed bitmap assets; it does not establish their draw order.
- `system.txt:11–42` defines palette cycling timings and explosion color/opacity values (`ASSET-17`), complementing the indexed images.
- `ACP00.cvr` begins `43 56 52 00` (`CVR\0`), and contains `AlienVehicle3.max` at byte `0x1C` (`ASSET-BYTES-4`). The embedded authoring filename is observed; the CVR geometry/voxel format is not decoded.
- `fx/gset1.amb` begins `prgm`, includes instrument names, and contains concrete sample paths such as `fx\bmarimba d4.wav` at `0x31A` (`ASSET-AMBIENT-PATHS`). `fx/dchoir a2.wav` parses as mono 16-bit PCM, 22,050 Hz (`ASSET-WAV`). Ambient scheduling/timing remains unknown.
- `movies/openingx.wve` begins `SCHl` (`ASSET-BYTES-12`); `movlist.txt:1–45` documents the movie lookup list (`ASSET-24`). The codec and playback implementation require executable evidence.

The save checks are intentionally limited. All three `.SAV` files are 290,608 bytes and begin `54 45 52 52 41 4E 00 1A 56 00 00 00` (`TERRAN\0\x1A`, then little-endian integer 86 at offset 8). The shipped `Build.SC` has the identical first 12 bytes. `maps/planet.MP` instead begins `TERRANMAP\0\x1A`, then little-endian integer 5 at offset 11. The shared save/scenario prefix suggests a common format family; interpreting the integers as version numbers is unverified. Full serialization layout, compression, integrity checking, and state reconstruction were not recovered. The shipped readme also explicitly warns that encrypted Alpha Centauri multiplayer saves do not work with Alien Crossfire (`ASSET-23`), so shared prefixes do not prove interchangeability.
