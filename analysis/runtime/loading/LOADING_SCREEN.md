# Native game readiness and loading screen

The player now covers the entire framebuffer with an opaque loading screen before the original menu or game interface has drawn. Wine desktop/setup screens, the game's splash logo, and black intermediate frames stay covered. Start remains explicit for the browser's audio gesture. Preparation, start, elapsed loading time, and runtime errors have separate visible states. Runtime initialization alone does not reveal the game, and elapsed time never causes completion.

`public/native-ready.js` samples ten small regions from the two composited display canvases into a 160×8 scratch canvas: 1,280 pixels (5 KiB RGBA) per poll. Seven regions cover the repeated native main-menu buttons; three cover the gameplay HUD. It compares their average RGB patterns against observed original frames from both installed editions. All seven menu regions or all three HUD regions must match, twice consecutively, one second apart. The original display resolution is fixed at 1024×768; CSS scaling does not affect sampling. The sampler and elapsed timer stop permanently after reveal, adding no periodic work during gameplay.

The loader removes the canvases from focus/input while covered, restores keyboard focus when the game is shown, and preserves the existing save filesystem and shortcut adapter. An early window-capture gate blocks native coordinate-based listeners from receiving covered or modal input, including SDL's separate `keypress` path. It releases forwarded keys and captured mouse buttons on focus loss, modal opening, cancellation or blur, while preserving browser dialog defaults and native canvas shortcuts. Rejected fullscreen requests produce a local message and leave gameplay active. A runtime failure restores the opaque screen and disables guest input. Errors remain readable through the loading screen and Log. A missing/unrecognized native frame remains covered rather than being declared ready by a timer.

The fingerprints are generated by `tools/build_readiness_samples.py` from retained, visually confirmed original-game screenshots. Only tiny RGB averages are shipped in `public/native-ready-samples.json`; the provenance records reference paths and crop coordinates. The matcher is a conservative visual gate for this installed game's UI, not a parser of native simulation state. Custom menu skins or future layout changes need new fingerprints and compatibility testing.

Validation:

- `node tools/test_native_readiness.mjs`: 17 retained screenshots. Both edition menus and four native world frames match; nine Wine, blue, splash, startup, and error frames stay unready.
- `node tools/test_native_loading.mjs`: real player DOM with a stub emulator, extracted native window-capture handlers, the generated SDL keypress listener, and native screenshot replay. Checks initialization/blue/splash remain covered, two-sample reveal, both editions, restored focus, no sampling after reveal, error coverage, host Tab/Enter/Escape, held input release, drag outside the canvas, Ctrl/Command shortcuts and nonfatal fullscreen rejection. It does not execute the native game or touch its save files. The added SDL listener reproduced Enter failing before the keypress gate was added. [Results](dom-validation.json).
- Prescribed develop-web-game Playwright client run after final changes; ready-to-start screen and diagnostics inspected.

Live emulator readback also passed on the unchanged runtime baseline: all seven menu regions matched, and two samples recognized the actual Alien Crossfire menu at approximately 197.25 seconds. The baseline screenshot was visually inspected. See [baseline menu metrics](../../performance/baseline/menu-baseline.json), especially `nativeReady`, and `../../performance/baseline/boot-current.png`.

The optimized live run subsequently showed the opaque [loading cover](../../performance/optimized/loading-live.png) and automatically revealed the [original menu](../../performance/optimized/menu-ready.png), with two matching samples at 59.273 seconds after auto-Start. A full Chromium restart with persisted storage also automatically revealed the menu at 42.908 seconds. These confirm the complete cover-to-native-reveal path on the actual emulator, separately from screenshot replay. [Measurements and native acceptance](../../performance/PERFORMANCE.md).
